## Goal
Under chaos (60% of model calls fail, seeded) 20 of 20 Requests get an answer and the report names
the Serving tier. In a total outage, template tasks still return code and tests; an unknown task
gets "cannot generate now" plus a Ticket, never invented code. A degraded tier never auto-approves.

## Design

### Pure rules: `src/codeforge/policy/resilience.py` (no I/O, no clock, no globals)
- `is_transient(kind)`: only `rate_limit` (429), `server_unavailable` (503), `timeout` are retried.
  Bad output is **not** transient: it goes straight to the fallback.
- `backoff_delay(attempt, rng)`: exponential with full jitter, capped. `rng` is passed in.
- `BreakerState` (frozen) + `next_state(state, success, now)`: closed → open after N consecutive
  failures; open → half-open after cooldown; one probe decides. `now` is an argument.
- `pick_template(request) -> TemplateMatch | None`: keyword rules with required and blocking
  words; **exactly one** match, else `None`. Look-alike Requests are unit-tested.

### Wrapper: `src/codeforge/llm/resilient.py`
`ResilientCaller(primary, fallback, breaker, sleep, rng, clock)` implements `StructuredCaller`.
Order per call: primary (retry transient, jittered) → on bad output / exhausted retries / open
breaker → fallback (small model, same rules) → raises `ModelUnavailableError`.
Records the **Serving tier** actually used (`large`, `small`, `template`) on the caller so the graph
can read it. Caller errors get a typed `kind` (needs `GroqCaller` to classify 429/503/timeout
instead of the blanket `ModelUnavailableError`).

### Chaos switch: `src/codeforge/llm/chaos.py`
`ChaosCaller(inner, rate=0.6, seed=...)` wraps a caller; seeded `random.Random`; injects a mix of
429, 503, timeout and bad output. Enabled by config (`CODEFORGE_CHAOS_RATE`, `CODEFORGE_CHAOS_SEED`;
added to `ENV_KEYS` and `.env.example`, test enforces). Default off.

### Template tier: `src/codeforge/agents/templates.py`
A small fixed set of hand-written functions + tests (e.g. sum list, reverse string, palindrome,
factorial). Used when both models are unavailable. No match or ambiguous → `cannot_generate` +
Ticket. Template code/tests still go through the policy gate and approval.

### Graph wiring
- `Nodes` reads the tier from the caller; state gains `serving_tier`; the report already has the
  field (`ReportInput.serving_tier`, runs table column exists), so the template line gets filled.
- Degraded tier fail-closed: `policy` node turns `allow` into `needs_approval` when tier is
  `template`/`small` (never auto-approves; today nothing yields `allow`, so this is guarded by a test
  rather than behaviour change).
- Template path: on total outage, requirements/codegen/testgen nodes ask `pick_template`; one match →
  fill requirements, code and tests from the template; else `cannot_generate`.

### Ticket (dependency on R3, UNRESOLVED)
The Ticket store belongs to R3 (#8), not built. Proposal: R5 calls a `TicketSink` protocol; until R3
lands the sink records a minimal ticket row in SQLite (user, masked request, reason, tier). R3 then
owns richer fields. **Decision needed:** build the minimal ticket here, or wait for #8.

## Tests (test-first)
1. `tests/unit/test_resilience_rules.py`: transient vs not, jitter bounds, breaker transitions,
   template match (exactly one; required/blocking words; look-alikes such as "sum of digits",
   "reverse a linked list", "delete files then sum").
2. `tests/unit/test_resilient_caller.py`: retry only transient; bad output → fallback without retry;
   open breaker skips primary; tier recorded.
3. `tests/unit/test_chaos.py`: same seed → same failure sequence; ~60% over many calls.
4. `tests/unit/test_graph.py` additions: outage + template task → code, tests, tier named; outage +
   unknown → `cannot_generate` + ticket; degraded tier never auto-approves.
5. Chaos run script `scripts/chaos_run.py`: 20 Requests, log saved to `plans/` or `evals/` for the
   submission. Uses a fake model underneath so it is offline and deterministic; a live variant
   needs the Groq key.
6. Golden cases (hard): outage template task, outage unknown task, degraded-never-auto-approve.
   Depends on R6 gate (#6) existing; until then they live as unit tests.
