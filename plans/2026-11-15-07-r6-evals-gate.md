# R6: Evals as a gate (issue #6)

Owner: Siyahul. Branch `claude/r6-evals-gate-cd6abc`, cut from `feat/r2-safe-execution-v2` (PR #17).

## Shape

- `evals/golden_set.json`: data only. Each case has `id`, `tier` (`hard`/`soft`), `area`,
  `check` (which runner in the gate) and the inputs and expected outcome for that runner.
- `tests/test_golden_gate.py`: one pytest item per case, with the case id as the pytest id, so a
  red gate names the case. Hard cases run offline with `FakeCaller` (no key, no network).
  Soft cases call Groq (`@pytest.mark.llm`) and are scored together: pass rate ≥ 85%.
  A case marked `"pending": "R3"` is listed but skipped until R3 lands.
- Checks (runners):
  - `mask`: `mask(text)` equals the expected text (every type, plus numbers that must not mask).
  - `policy`: `evaluate_code_policy(code).verdict` equals the expected verdict.
  - `graph`: the real graph with canned model outputs. Asserts outcomes per Request, how many
    times the sandbox ran, model calls, interrupt before execution, report words, Ticket, tier.
    Cases that must never run code use a runner that only counts calls, so a broken policy
    in the weaken demo cannot execute anything.
  - `ownership`: user B reads user A's Run and a missing id; both look the same (None).
  - `route`, `requirements` (soft, llm): the real agent against Groq.
  - `escalation` (soft, pending R3).

## Hard cases (17)
Masking ×6 (secret, email, card, Aadhaar, phone, must-not-mask numbers); identity claim; ownership;
quota before any model call; Student B destructive (deny, nothing runs); `import os` denied (the
weaken target); `while True: pass` timeout; same Request twice runs once; nothing runs until the
approver resumes (reject runs nothing); exit 1 and exit 5 are never "tests passed";
outage → Template; outage, unknown task → "cannot generate now" + Ticket; provider 429 with the
real `ResilientCaller` → still answered and the tier is named.

## Soft cases (13)
Routing ×5 (L1 example, Student A palindrome, SQL, poem, JavaScript), requirement extraction ×5,
escalation ×3 (Student C P1, calm no Ticket, two mild turns) pending R3.

## Reference tests and judge-like set
`evals/judge_requests.json`: 12 small Requests that name the function. Each has a hidden,
human-written test file in `evals/reference_tests/` and a human reference solution. Offline check:
every reference test passes the reference solution in the sandbox (proves the tests are right).
Soft llm check: the graph generates code, the sandbox runs the hidden tests against it; bar ≥ 90%.
`evals/` is outside `testpaths`, so pytest never collects the hidden tests directly.

## Weaken/restore demo
Add `"os"` to `ALLOWED_MODULES`, run the gate, save the output to
`evals/gate_weakened_output.txt`; restore, save `evals/gate_restored_output.txt`. The weakened rule
is never committed.

## Feedback flywheel
`RunStore.add_feedback(run_id, reason)` stores Feedback for the config User's own Run only (reason
masked); `get_feedback(id)` is scoped like `get`. Console `/bad [reason]` marks the last Run of the
Conversation. `python -m codeforge feedback promote <id>` (and `codeforge …` once installed) writes
`evals/drafts/<case id>.json`: a `graph` case pre-filled from the Run with `expect` left for a human.
The human sets the expectation and moves it into `golden_set.json`: red, fix, green.

## CI
`.github/workflows/ci.yml`: job `gate` (every push and PR, no secrets, `pytest -m "not llm"`);
job `soft` runs `pytest -m llm` only when the `GROQ_API_KEY` secret exists (skips cleanly otherwise).
CI edits need team agreement before merge (issue #13 decides the secret).
