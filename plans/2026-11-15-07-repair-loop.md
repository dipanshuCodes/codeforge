# Repair loop: plan (issue #7)

Status: **in progress** (branch `feat/repair-loop`). Updated after R2 (#17) and R5 (#15) landed on main. To be put to the team before building (issue step 3). Owner: Dipanshu.
Scope source: problem statement "Repair loop" (plan 01 §Execution key / Repair loop); CONTEXT.md "Repair attempt".

## Goal
A Run whose tests fail gets up to 2 Repair attempts (1–3 Executions). Repair 1 changes the code only;
repair 2 may also change the tests, but never to weaker ones. Every repair goes back through the
policy gate. The report shows the real final pytest result and says how many repairs were tried.

## Design

### Pure rules: `src/codeforge/policy/repair.py` (no I/O, no model calls, no globals)
- `count_tests(source: str) -> int`: top-level `test_*` functions plus `test_*` methods of `Test*` classes, by `ast`.
- `count_assertions(source: str) -> int`: `assert` statements whose test is not a constant (`assert True` doesn't count) plus `with pytest.raises(...)` blocks.
- `evaluate_repair(attempt: int, old_code: str, old_tests: str, new_code: str, new_tests: str) -> RepairDecision`
  with `RepairDecision(accepted: bool, reasons: list[str])`. Rejects when:
  - either source does not parse (fail closed);
  - the code and tests are both unchanged (a no-op repair is not an attempt worth executing; the Execution key would only replay the old result);
  - attempt 1 and the tests changed at all;
  - attempt 2 and `count_tests` or `count_assertions` is lower than before;
  - attempt 2 adds `skip`, `skipif` or `xfail` markers or `pytest.skip(` calls that weren't there (fewer effective tests by another route).
- `should_repair(outcome, attempts_used, max_attempts, serving_tier) -> bool`: only for `tests_failed`; never for `timed_out`, `denied`, `rejected` or `cannot_generate`; never on the `template` tier (no model to ask).

### Agent: `src/codeforge/agents/repair.py`
`repair_code(caller, req, code, tests, pytest_output) -> CodeOutput` (repair 1) and
`repair_code_and_tests(caller, req, code, tests, pytest_output) -> RepairOutput` (repair 2; new schema
`RepairOutput(code, tests)` in `schemas.py`). Pytest output is passed through `mask()` before it goes in
a prompt. Agents decide nothing.

### Graph
- New node `repair` between `execute` and `policy`. `after_execute` routes to `repair` only when `should_repair(...)` is true, otherwise `report` (replaces the current `attempts <= max` edge to `codegen`).
- `repair` node: calls the agent for `repairs_tried + 1`, runs `evaluate_repair`. Accepted → stores new code (and tests), → `policy` → (approval) → `execute`. Rejected by the rule → counts as a failed attempt, old code stays, loops back to `repair` if budget remains, else `report`. Model error → stop repairing, `report` shows the previous real result.
- `execute` already consults the Execution key. If a repair somehow yields code + tests seen before, the result comes back with `reused: True`; the report must say the Execution was reused rather than re-run.
- State: `repairs_tried: int` (add to `RunState` and `RUN_DEFAULTS`). `attempts` keeps counting Executions.
- Policy deny or approver reject after a repair → existing `denied` / `rejected` outcomes; the report still shows the last real pytest result and the repair count.
- After the second failed repair: `store.add_ticket(run_id, "P3: two failed repairs", tier, request)` and set `ticket_id`. The `tickets` table has no priority column, so the signal lives in the reason until R3 (#8) owns Tickets.

### Config and report
- `Settings.max_repair_attempts` default 0 → 2. No new env key, so `ENV_KEYS` and `.env.example` stay as they are.
- `ReportInput` gains `repairs_tried` and `max_repairs`; the report gets a line `Repairs:      1 of 2 tried`. The headline still comes only from the real pytest exit code.

## Tasks (each test-first; commit after each)

1. **Repair rules.** `tests/unit/test_repair_rules.py` first, then `policy/repair.py`. Cases: deleting a failing test is rejected; dropping an assertion is rejected; replacing a real assert with `assert True` is rejected; adding `@pytest.mark.skip` is rejected; repair 1 touching tests is rejected; unchanged code is rejected; unparsable output is rejected; repair 2 adding a test is accepted; a code-only repair 1 is accepted; `should_repair` table (every outcome × tier).
2. **Repair agent.** `tests/unit/test_agents.py` additions with the fake caller: prompt contains the masked pytest output and not an unmasked key; bad output raises `ModelOutputError`.
3. **Graph wiring.** `tests/unit/test_graph_repair.py` with a scripted fake caller and fake `run_tests`: fail → repair 1 → pass (2 Executions, report says 1 repair, "TESTS PASSED"); fail → fail → fail (3 Executions, P3 Ticket, "TESTS FAILED", 2 repairs); repair that deletes a test is rejected and counted; repaired code that fails policy → `denied`, nothing executes; reject at approval after a repair → `rejected`; timeout is not repaired; template tier is not repaired; a second Request on the same thread starts with `repairs_tried = 0`. a repair that passes policy as `allow` executes without an approval prompt; a repair returning identical code is rejected before any Execution. Update `test_graph.py::test_failing_tests_no_repair_in_l1` to set `max_repair_attempts=0` explicitly.
