# R3 Escalation and handoff: plan (issue #8)

Status: **built** (PR open; live Groq check open) · Owner: Siyahul · Branch `claude/r3-escalation-991c57` (cut from R2 `feat/r2-safe-execution-v2`).
Scope source: issue [#8](https://github.com/dipanshuCodes/codeforge/issues/8); AGENTS.md pass condition R3.

## Goal
Student C ("THIS IS NOT WORKING!!! get me a human" + key + Aadhaar) opens a P1 Ticket with no key
or Aadhaar and nothing is generated. A calm Request opens no Ticket. Two mildly unhappy turns in
one Conversation escalate, though neither alone does.

## Design

### Pure rules: `policy/escalation.py`
- `Signals` (frozen): `wants_human`, `sentiment`, `urgency`, plus Conversation counters
  `unhappy_turns`, `denials`, `failed_repairs`.
- `decide_escalation(signals) -> Escalation | None`, first match wins:

  | Rule | Priority | SLA |
  |---|---|---|
  | `wants_human` and (angry or high urgency) | P1 | 1 h |
  | angry, or `wants_human` alone | P2 | 4 h |
  | 2+ `mildly_unhappy` turns | P3 | 24 h |
  | 2+ policy denials | P3 | 24 h |
  | 2+ failed Repair attempts | P3 | 24 h |

- `opens_ticket(new, already_opened)`: open a Ticket only if this Conversation has none yet, or
  the new priority is stricter. Stops a Ticket per turn once a Conversation has escalated.
- `skips_generation(priority)`: only P1.

### Agents
- `agents/triage.py`: one structured call (`TriageOutput`: language, sentiment, urgency,
  wants_human; no task type) on the **masked** Request, through the existing resilient caller.
  Any model failure → safe defaults (calm / low / no human); the Run continues.
- `agents/handoff.py`: one call to the **small** model for 1–2 advisory sentences from masked
  Ticket fields. `build_graph(..., summary_caller=)`; the console builds it from
  `settings.small_model` (chaos-wrapped when chaos is on). Failure or no caller → absent.

### Handoff note: `reporting/handoff.py`
`HandoffNote`: template summary line (always), AI summary (re-masked with `mask`, optional),
masked Request, attempts, last failing test (first `FAILED …` line of pytest output).

### Store: extend `runs/store.py`
`tickets` gains `priority`, `sla_hours`, `handoff_note` (JSON), added with `ALTER TABLE` when
missing, like `runs`. `add_ticket` takes them as optional keywords, so R5's outage Ticket is
unchanged. Still scoped to the config User.

### Graph
- Conversation counters live in graph state outside `RUN_DEFAULTS`, so they survive between
  turns of one `thread_id` (in-memory checkpointer).
- `triage` calls the agent and counts a mildly unhappy turn.
- `escalation` decides; P1 opens a Ticket and routes straight to `report` with outcome
  `escalated` (new Final outcome: a repeat of the same message returns the stored Run);
  P2/P3 open a Ticket and continue.
- `report` counts this Run's denial / failed Repair attempts and decides again, so the second
  denial escalates in the Run where it happens, not one turn later.
- The report states the Ticket priority, SLA and id.

## Decisions / UNRESOLVED
- Failed Repair attempts accumulate across the Conversation, counted from the repair loop's
  `repairs_tried` (#18; a rejected repair counts). The loop's own minimal "two failed repairs"
  Ticket is replaced by this rule's P3 Ticket with a Handoff note.
- Triage failure during an outage means "get me a human" gets no escalation from triage. The
  R5 outage Ticket still opens when nothing can be served. UNRESOLVED: a keyword fallback.
- Counters are lost on restart (checkpointer is in memory), like the Conversation itself.
